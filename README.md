# CPRISK — ระบบบริหารความเสี่ยง รพ.ชุมแพ (MOCK/DEMO)

ระบบกรอกอุบัติการณ์ความเสี่ยง "กรอกครั้งเดียวที่ รพ." — เก็บลงฐานข้อมูลของ รพ. ก่อน
กรรมการความเสี่ยงรับเรื่อง-ตอบกลับได้ทันที แล้วค่อยส่งเข้าเว็บกลาง NRLS (แนวเดียวกับระบบ SSCC Stroke)

> **สถานะปัจจุบัน: MOCK สำหรับเดโม** — ข้อมูลทั้งหมดเป็นข้อมูลจำลอง
> ปุ่ม "ส่งเข้า NRLS" เป็นการจำลอง ไม่เชื่อมต่อเว็บ cphos.thai-nrls.org จริง

## วิธีเปิดเดโม

1. ดับเบิลคลิก `app\start.bat` (ต้องมี Python + `pip install flask`)
2. เบราว์เซอร์เปิด http://127.0.0.1:8548 เอง
3. ฐานว่างครั้งแรกจะ seed ข้อมูลจำลอง ~380 เคสให้อัตโนมัติ (กราฟสวยตั้งแต่เปิด)

### ท่าเดโมแนะนำ (ขายไอเดีย "ตอบสนองเร็ว")

เปิด 2 หน้าต่างเบราว์เซอร์วางคู่กัน:
- จอซ้าย: **📝 รายงานอุบัติการณ์** — กรอกเคสใหม่ เลือกระดับ E ขึ้นไป แล้วกดส่ง
- จอขวา: **📥 งานกรรมการความเสี่ยง** — เห็นกระดิ่งแจ้งเตือนเด้ง (ภายใน ~10 วิ) เคสใหม่ขึ้นแถบแดงบนสุด
- จากนั้นกดรับเรื่อง → บันทึกการแก้ไข → ปิดเคส → โชว์ไทม์ไลน์ + Dashboard ที่ตัวเลขขยับ
- ปิดท้าย: จากหน้าเคส กด **🚀 ส่งเข้า NRLS** → เปิดเว็บ NRLS จำลอง กด "เริ่มกรอกอัตโนมัติ"
  ให้คนดูเห็นระบบกรอกทีละช่อง แล้วกรรมการกดบันทึกเอง — ขายไอเดีย "กรอกครั้งเดียว + human-in-loop"

## หน้าในระบบ

| หน้า | สำหรับ | มีอะไร |
|---|---|---|
| `/report` | เจ้าหน้าที่หน้างาน | ฟอร์มตามโครงเว็บ NRLS จริง ฟิลด์ซ่อน/โชว์ตามเงื่อนไข |
| `/inbox` | กรรมการความเสี่ยง | เคสเรียงรุนแรงก่อน แท็บตามสถานะ ค้นหาได้ |
| `/case/<id>` | กรรมการ | รายละเอียด + รับเรื่อง/บันทึกแก้ไข/ปิดเคส/ส่ง NRLS (จำลอง) + ไทม์ไลน์ |
| `/dashboard` | ผู้บริหาร | KPI + donut แบบ HRMS + เวลาตอบสนอง/เคสค้าง แยกรายหน่วยงาน |
| `/nrls-sim/<id>` | กรรมการ | **เว็บ NRLS จำลอง** (โคลนโครงฟอร์ม HRMS v6.3) — กดจากหน้าเคส ระบบกรอกให้ทีละช่อง กรรมการตรวจทานแล้วกดบันทึกเอง (สาธิต human-in-loop ของ P1) |
| `/channels` | ผู้บริหาร | ตารางเปรียบเทียบช่องทางแจ้งเตือน (ในระบบ/LINE OA/อีเมล/SMS) เพื่อการตัดสินใจ |
| `/fields` | ผู้ดูแล | เพิ่มหัวข้อ/ตัวชี้วัดที่ รพ. อยากเก็บเอง โผล่ในฟอร์มทันที |
| `/qr` | ที่ประชุม/เดโม | QR สแกนเข้า GitHub ของโปรเจกต์ (github.com/mkungsuki/CPRISK — เปลี่ยนได้ใน config) |

## โครงทางเทคนิค

- Flask + SQLite (JSON ต่อแถว) + Chart.js (ฝังไฟล์ ใช้ offline ใน intranet ได้) — ไม่พึ่งเน็ตนอก
- ฟอร์มขับด้วย `app/schema/hrms_fields.json` — แก้/เพิ่มฟิลด์โดยไม่ต้องแตะโค้ด
- เกณฑ์เคสรุนแรง + SLA ตั้งได้ใน `app/config.json` (`severe_clinical`, `severe_general`, `sla_*`)
- ล้างข้อมูลเดโม: ลบ `app/data/cprisk.db` แล้วเปิดใหม่ (seed ใหม่อัตโนมัติ; ปิด seed ได้ด้วย `demo_seed: false`)

## แผนไประบบจริง (P1 — หลังผ่านเดโม)

1. **ส่งเข้า NRLS จริง**: เขียน `fill_hrms.py` ตาม pattern `fill_sscc.py` ของ SSCC (Playwright + Edge,
   จำ session, เข้าคิว, กรรมการตรวจทานบนเว็บก่อนกดบันทึกจริงเสมอ) + เก็บ dropdown/รหัสชุดเต็มจากเว็บจริง
2. **Multi-user จริง**: ย้ายขึ้นเครื่องใน intranet รพ. (บริหารคุยกับ IT) + login/สิทธิ์ 3 ระดับ
3. **ช่องทางแจ้งเตือน**: ตามที่บริหารเลือกจากหน้า `/channels`
4. Export รายงาน HA (Excel) — ยกโค้ด `excel_export.py` จาก SSCC

เอกสารประกอบการวางแผน: `C:\SSCC\_intake\hrms-risk-spec.md` และ `C:\SSCC\_scout\hrms-risk-scout-report.md`
