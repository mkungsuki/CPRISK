# Spec Sheet: hrms-risk (ระบบบริหารความเสี่ยง รพ.ชุมแพ)

**Date:** 2026-08-21
**Raw request (verbatim):** "ได้งานมาเพิ่ม เป็นงานแนวทำ dash board บริหารคตวามเสี่ยง รพ และร้องเรียนความเสี่ยงที่ขึ้เนเลนย แต่ว่าปกติถามเขาว่าทำไง เขาบอกว่ามันจะเป็นรายงานความเสี่ยงผ่านเวปกลางของรัฐ เลยคิดว่า ถ้าทำเป็นตัวของ รพ ที่สร้างข้อมูลออกมาในฐานก่อนยิงเข้าไปกรอกให้ในนี้ มันจะลด friction ของคนใช้ได้ คล้ายแบบ SSCC"

## Problem
- **โจทย์:** ระบบกรอกอุบัติการณ์ความเสี่ยงของ รพ.ชุมแพ ที่เก็บข้อมูลในฐานของ รพ. เองก่อน แล้วยิงเข้ากรอกในเว็บกลาง HRMS/NRLS (cphos.thai-nrls.org) แบบ human-in-loop พร้อมแจ้งเตือนผู้รับผิดชอบเมื่อความเสี่ยงสูง วงจรตอบกลับ "แก้ไขแล้ว" เก็บเป็นหลักฐาน/ตัวชี้วัด และ dashboard ใช้ง่ายทุกฝ่าย
- **ผู้ใช้ 3 กลุ่ม:**
  1. ผู้กรอก — พยาบาล/หมอ/เจ้าหน้าที่ทุกหน่วยงาน (multi-user หลายฝ่าย)
  2. กรรมการ/ผู้ดูแลความเสี่ยง — รับเรื่อง ตรวจข้อมูล ตอบกลับ วางแผนทันท่วงที
  3. ผู้บริหาร — ดูข้อมูล/ตัวชี้วัดเพื่อนำเสนอ HA และวางแผน
- **ทำไมต้องสร้าง:** ตอนนี้รายงานตรงเข้าเว็บกลางรัฐ → ต้องขอดึงข้อมูลออกมาประเมิน → ตอบสนองช้า ติดหลายขั้นตอนเอกสาร ไม่มีภาพรวมของ รพ. เอง

## I/O Contract
- **Input:** ฟอร์มอุบัติการณ์ (ฟิลด์ชุดเดียวกับ HRMS เพื่อ map 1:1 + ฟิลด์/ตัวชี้วัดภายในที่ รพ. เพิ่มเองได้แบบ SSCC custom fields)
- **Output:**
  1. คิว draft → กรรมการตรวจ → กดยิงเข้า HRMS (human-in-loop, ไม่ auto-fire)
  2. แจ้งเตือน 2 ระดับ: ของแรง = active alert ถึงผู้รับผิดชอบ / ของไม่แรง = เห็นง่ายในหน้ารวม
  3. Dashboard + export รายงานตัวชี้วัดสำหรับ HA
- **Success criteria (ยืนยันแล้ว):**
  - กรอก 1 เคสจบ ≤ 5 นาที ไม่ต้องเข้าเว็บ HRMS เอง
  - เคสความเสี่ยงสูงถึงมือกรรมการภายในไม่กี่นาที
  - ข้อมูลใน HRMS ตรงกับฐาน รพ. 100% ตรวจย้อนได้
  - ผู้บริหารดึงรายงานเองได้จาก dashboard

## Constraints
- **Hosting:** intranet รพ. (คาดการณ์) — การจัดหาเครื่อง/เซิร์ฟเวอร์เป็นเรื่องที่บริหารไปคุยกับ IT รพ. เอง เราทำ mock บนโครงที่ย้ายไปวางได้
- **Timeline:**
  - **Mock กดได้จริง ภายใน 2 วัน** (มีของโชว์ว่ากำลังพัฒนา)
  - เดโมให้ HA ดูได้ อาทิตย์หน้า
  - ระบบสมบูรณ์: ไม่รีบ
- **Stack:** แนวเดียวกับ SSCC (เว็บ local + ฐานข้อมูลใน รพ. + ตัวยิงเข้าเว็บกลาง)
- **Privacy:** ข้อมูลอุบัติการณ์ผู้ป่วย — อยู่ใน รพ. ไม่ออก cloud ภายนอก

## Non-functional Requirements
- Multi-user พร้อมกันหลายหน่วยงาน (ต่างจาก SSCC ที่ admin คนเดียว)
- แบ่งบทบาท: ผู้กรอก / กรรมการ / ผู้บริหาร
- UI ง่ายสำหรับคนหน้างานทุกฝ่าย (เกณฑ์สำคัญที่ผู้ใช้ย้ำ)
- Mock ต้องรันเดโมได้จากเครื่องเดียว และเปิดหลายหน้าต่าง/หลายเครื่องโชว์ "กรอกจอนี้ เด้งจอโน้น" ได้

## Architecture Decisions Already Made (ห้าม re-debate)
- **ไม่ยิง HRMS อัตโนมัติทันที** — เก็บเป็น draft/คิว ให้กรรมการตรวจก่อนกดยิง (human-in-loop กันข้อมูลพลาด)
- **แจ้งเตือน 2 ระดับ** — แรง (เช่น E ขึ้นไป / G,H,I / 3,4,5 — ตั้งค่า cutoff ได้) = active alert; ไม่แรง = เด่นในหน้ารวม
- **ช่องทางแจ้งเตือนไม่ตัดสินใจแทน** — ทำหน้านำเสนอตัวเลือก (LINE Messaging API / ในระบบ / อีเมล + ข้อดี-เสีย-ค่าใช้จ่าย) ให้บริหารเลือก กันผู้พัฒนากลายเป็นผู้ดูแลถาวร
- **Mock = เว็บเดโมกดได้จริง ข้อมูลปลอม** — ฟอร์ม→คิวกรรมการ→ตอบกลับ→dashboard ขยับตาม + หน้าเลือกช่องทางแจ้งเตือน; ปุ่ม "ส่งเข้า NRLS" เป็น simulate ไม่ยิงเว็บรัฐจริง (ห้ามยิงข้อมูลปลอมเข้าระบบจริง)
- **Dashboard หลักหน้าตาแนว HRMS** (donut ตามหมวด Safety Goals + ระดับรุนแรง คนดูคุ้นตา) **+ ตัวชี้วัดที่เว็บกลางให้ไม่ได้** (เวลาตอบสนอง, เคสค้าง, อัตราปิดเคสรายหน่วยงาน) **+ เพิ่มตัวชี้วัด/ฟิลด์เองได้แบบ SSCC** — จุดขาย "พัฒนาได้กว่าเดิม"
- **ฟิลด์ฟอร์มยึดตามฟอร์มจริงของ HRMS** (บันทึกรายงานอุบัติการณ์) เพื่อ map 1:1 ตอนยิงจริงภายหลัง

## Priority Tiers
- **P0 (mock ภายใน 2 วัน):** ฟอร์มกรอกตามฟิลด์ HRMS + คิวกรรมการ (รับเรื่อง/ตอบกลับ/mark ส่ง NRLS) + dashboard (donut แบบ HRMS + response-time metrics) + หน้ารวมเคส 2 ระดับ + หน้าเลือกช่องทางแจ้งเตือน + ข้อมูลปลอม seed
- **P1 (ก่อนใช้จริง):** ยิงเข้า HRMS จริง (แบบ SSCC queue), ระบบ user/สิทธิ์จริง, custom fields/ตัวชี้วัดเพิ่มเอง, แจ้งเตือนช่องทางที่บริหารเลือก, export รายงาน HA
- **P2 (nice):** RCA tracking, ตัวชี้วัดตามหมวด SIMPLE, วิเคราะห์แนวโน้มรายปี
