# รายงาน Blind UI/UX Expert Review — CPRISK (2026-08-21)

> รีวิวโดย agent อิสระแบบ blind (ไม่รู้บริบทโปรเจกต์ ไม่อ่านโค้ด ผ่านเบราว์เซอร์เท่านั้น)
> ทำ research: Nielsen heuristics + severity 0–4, healthcare UX, WCAG 2.2, typography ไทย ก่อนลงมือ
> ตรวจครบ: /, /report, /inbox, /case/*, /nrls-sim/*, /dashboard, /channels, /fields × 3 ขนาดจอ (1280/768/375)
> พร้อมวัดค่าจริงด้วย getComputedStyle (contrast, font, touch target)

## 1) สรุปภาพรวม

### จุดแข็ง
1. **ฟอร์มรายงานออกแบบเพื่อหน้างานจริง** — section ชัด, ฟิลด์เงื่อนไข, รายงานนิรนามได้, ตัวเลือกเวรมีช่วงเวลากำกับ — คนไม่ใช่ไอทีกรอกได้ใน 5 นาทีตามที่อ้างจริง
2. **วงจรงานกรรมการครบ มี feedback ทุกจังหวะ** — timeline บันทึกเวลา/ผู้ทำ, กันปิดเคสโดยไม่สรุปผล, เคสรุนแรงมี badge + แถวไฮไลต์
3. **NRLS human-in-loop ทำได้ดีเป็นพิเศษ** — ปุ่มบันทึก disable จนกรอกเสร็จ, "ระบบไม่กดปุ่มนี้แทนคน" ชัดเจน, คำเตือนหน้าจำลองครบ
4. **Dialog ยืนยันลบฟิลด์เป็นตัวอย่างที่ดีมาก** — บอกผลที่ตามมา + เสนอทางเลือกเบากว่า (ปิดใช้แทนลบ)
5. **ภาษาไทยระดับดี** — ไม่มีศัพท์ไอทีเปลือย, hint ภาษาหน้างาน, lang="th", โครง heading ถูกต้อง

### ความเสี่ยงใหญ่สุด 3 ข้อ
1. **ไม่มี auth/สิทธิ์เลย** — ใครก็เข้า inbox, ทำการในนามคนอื่น ("ดำเนินการในนาม" พิมพ์อิสระ prefill "พว.ปนัดดา"), ลบฟิลด์ได้ — ทำลายวัฒนธรรม non-punitive reporting
2. **สี severity อ่านแทบไม่ออกและสื่อกลับด้าน** — ขาวบนเหลือง (3/F) contrast **1.40:1**; ระดับ **E ซึ่งเป็นเกณฑ์รุนแรงของระบบเอง ใช้สีเขียวมะนาว** (1.80:1) — ข้อมูล safety-critical ที่สุดอ่านยากที่สุด
3. **inbox + หน้าเคสพังบนมือถือ** — เนื้อหาบีบไม่ลง 375px (inbox กว้าง 574px, case 439px) → ทั้งหน้าถูกซูมออก ตัวอักษรจริง ~9px ลิงก์เลขเคส ~20×12px

## 4) Accessibility (ตัวเลขวัดจริง)

Contrast (AA 4.5:1): Badge 3/F ขาวบนเหลือง **1.40:1** ❌, E **1.80:1** ❌, A 2.07 ❌, 4/G 2.37 ❌, D/1/B/2/C 2.50–3.31 ❌, 5/I แดง 4.98 ✅ (สีเดียวที่ผ่าน), ปุ่มส่ง 4.17 ❌เฉียด, hint 4.48 ❌เฉียด, เมนู header ~6.8 ✅

Touch targets: radio+label 33px ✅ขั้นต่ำ, nav 31px, ปุ่มหลัก 38–63px ✅, ลิงก์เลขเคส 31×19px ❌ (มือถือเหลือ ~20×12px)

โครงสร้าง: lang="th" ✅, heading ถูกลำดับ ✅, native controls ใช้คีย์บอร์ดได้ครบ ✅, ไม่มี custom :focus style, 17/27 controls ไม่มี label ผูก, กราฟ canvas ไม่มีทางเลือกข้อความ, line-height ต่ำ

## 5) คะแนน UX ต่อกลุ่มผู้ใช้

| กลุ่ม | คะแนน | เหตุผลย่อ |
|---|---|---|
| เจ้าหน้าที่หน้างาน | **7/10** | ฟอร์มคือส่วนที่ดีที่สุด; หัก error ไม่ชี้จุด, วันที่ไม่ validate, ส่งแล้วตามเคสตัวเองไม่ได้ |
| กรรมการความเสี่ยง | **6/10** | workflow ครบ + NRLS ดี; หักตาราง 384 แถว, badge อ่านยาก, ปิดเคสแก้ไม่ได้, มือถือพัง |
| ผู้บริหาร | **6.5/10** | KPI ตรงใจงาน HA, /channels น่าชื่นชม; หักไม่มี export, ไม่ drill-down, ไม่มีสิทธิ์ผู้ใช้ |

**บทสรุป:** โครงกระดูกแข็งแรง — โมเดล "กรอกครั้งเดียว, human-in-loop, วงจรปิด" ถูกต้องตามหลัก healthcare UX ลำดับแก้ก่อนใช้จริง: (1) สิทธิ์ผู้ใช้ (2) สี severity ทั้งชุด (3) mobile inbox/case (4) validation วันที่ + ช่องทางติดตามเคส — แก้ได้โดยไม่ต้องรื้อสถาปัตยกรรม
