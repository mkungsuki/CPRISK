# รายงาน Blind Usability Test — CPRISK (2026-08-21)

> ทดสอบโดย agent อิสระแบบ blind (ไม่รู้บริบทโปรเจกต์ ไม่อ่านโค้ด ประเมินผ่านเบราว์เซอร์เท่านั้น)
> ทำ research แนวปฏิบัติ hospital incident reporting + usability testing ก่อนลงมือ
> ข้อจำกัด: ประเมินผ่าน accessibility tree/DOM — ไม่ครอบคลุมความสวยงามเชิงภาพ

## 1) สรุปผู้บริหาร

ระบบทำภารกิจหลักได้ครบวงจรจริง: พยาบาลมือใหม่รายงานเคสจบได้เองใน ~13 ขั้นโดยไม่ต้องมีใครสอน กรรมการเดินเคสจนถึงส่ง NRLS จำลองได้เอง และผู้บริหารตอบคำถามหลักจาก dashboard ได้ใน 1 นาที จุดแข็งตรงกับงานวิจัยเรื่องลด underreporting หลายข้อ (ฟอร์มสั้น มีช่องไม่ระบุตัวตน มี feedback loop กลับหน่วยงาน) แต่มีจุดสะดุดสำคัญ 3 เรื่อง: **เคสใหม่ระดับไม่รุนแรงจมอยู่ลำดับ ~100 ของรายการกรรมการ**, **ระบบเซ็นชื่อ default ("พว.ปนัดดา") ลงไทม์ไลน์ให้เองโดยผู้ใช้ไม่รู้ตัว** (กระทบความน่าเชื่อถือของหลักฐาน), และ**กดส่งฟอร์มว่างแล้วเงียบ ไม่มีข้อความ error ใดๆ** โดยรวมพร้อมใช้เป็น pilot ใน รพ. ได้หลังแก้จุดวิกฤตเหล่านี้ + เพิ่มระบบยืนยันตัวตน

## 2) ตารางผล Task

| Task | Persona | ผลสำเร็จ | SEQ (1–7) | จำนวนขั้นตอน |
|---|---|---|---|---|
| A รายงานเหตุให้ยาผิดคน (ระดับ D) | พยาบาลเวรดึก มือใหม่ | ✅ สำเร็จเอง ไม่ต้องเดา | **6** | 14 (1 คลิกเข้าฟอร์ม + 12 ช่อง + 1 ส่ง) — ได้เคส #382 |
| B รับเรื่อง→คืบหน้า→ปิด→ส่ง NRLS | กรรมการความเสี่ยงใหม่ | ✅ สำเร็จเอง (มีสะดุดตอน "หาเคสให้เจอ") | **5** | ~12 — ได้เลข NRLS-2026-00382 |
| C ตอบ 3 คำถามจาก dashboard | ผอ. มีเวลา 3 นาที | ✅ ข้อ 1–2 ตอบได้ใน <30 วิ / ⚠️ ข้อ 3 ต้องตีความเอง | **5** | 0 คลิก |

คำตอบที่ได้จริง: (1) ER มากสุด 56 เคส (2) ค้างเกิน 7 วัน = 120 เคส — มี KPI card บอกตรงๆ (3) ก.ค. 83 → ส.ค. 51 เคส *ดูเหมือน*ดีขึ้น แต่ ส.ค. ยังไม่จบเดือน — ระบบไม่บอก จุดนี้ผู้บริหารตีความผิดได้ง่าย

## 3) Friction Points (เรียงตามความรุนแรง)

### 🔴 รุนแรง
1. **[หน้าเคส] ระบบเซ็นชื่อ default ให้เอง** — บันทึกคืบหน้า/ปิดเคสโดยไม่กรอกช่อง "ดำเนินการในนาม" (อยู่ล่างสุด มองข้ามง่าย ค่าหายหลังทุก action) ไทม์ไลน์ขึ้นชื่อ "พว.ปนัดดา (กรรมการความเสี่ยง)" เองเงียบๆ → หลักฐานการดำเนินการเชื่อถือไม่ได้ **แก้:** บังคับกรอก/จำชื่อไว้ตลอด session ห้าม default เป็นชื่อบุคคลจริง
2. **[ฟอร์มรายงาน] กดส่งฟอร์มว่าง → เงียบสนิท** — ไม่มี error message ไม่ highlight ช่องที่ขาด **แก้:** แสดงข้อความ + เลื่อนไปช่องแรกที่ขาด
3. **[inbox] เคสใหม่ระดับ C/D จมอยู่ลึก** — เคสใหม่วันนี้อยู่แถว ~100 จาก 384 ใน default view; กรอง "🆕 รายงานใหม่" ก็ยังอยู่ลำดับ 7 **แก้:** default เรียง "ใหม่ก่อน" หรือคอลัมน์ sort ได้
4. **[ทั้งระบบ] ไม่มี login/บทบาทผู้ใช้** — ต้องมีก่อนใช้จริง (PDPA + ความเชื่อมั่นผู้รายงาน)

### 🟠 ปานกลาง
5. **[กระดิ่งแจ้งเตือน] ป้ายกับปลายทางไม่ตรงกัน** — กระดิ่ง 🔔5 = รุนแรง "ยังไม่รับเรื่อง" แต่คลิกไปหน้า "รุนแรง-ยังไม่ปิด" 27 เคส
6. **[ฟอร์ม] คำถามจำแนกกลุ่มเป็นศัพท์อังกฤษล้วน** — "Patient Safety Goals / Common Clinical Risk" ฯลฯ เดายาก และเคส "ให้ยาผิดคน" เข้าได้ 2 หมวดโดยไม่มีคำแนะนำ **แก้:** คำอธิบายไทย 1 บรรทัด/ตัวอย่างใต้ตัวเลือก
7. **[dashboard] กราฟแนวโน้มไม่เตือนว่าเดือนล่าสุดยังไม่จบ** + ไม่มีตัวสรุป "ดีขึ้น/แย่ลง X%"
8. **[inbox มือถือ] ตารางล้นจอแนวนอน** (541px ใน 345px) — ฟอร์มฝั่งพยาบาล responsive ดี

### 🟡 เล็กน้อย
9. **[inbox] ช่องค้นหาไม่ filter สด** — ต้องกด Enter (placeholder ดีมาก ค้น "Ceftriaxone" เจอจริง)
10. **[หน้าเคส] ปุ่มส่ง NRLS โผล่ตั้งแต่ยังไม่ปิดเคส** — ไม่มีคำแนะนำว่าควรส่งตอนไหน
11. **[ฟอร์ม] label ไม่ผูกกับ input** + กราฟ canvas ไม่มีตารางสำรอง → screen reader ใช้ไม่ได้
12. **[ยืนยันการส่ง]** บอกเลขเคส แต่ไม่มีวิธีให้ผู้รายงานตามเคสตัวเองภายหลัง

## 4) เทียบกับเกณฑ์งานวิจัย

**ทำได้ดี — ตรงกับปัจจัยลด underreporting:**
- ฟอร์มสั้นจบ ~5 นาที, progressive disclosure, ระดับ A–I มีคำอธิบายไทยทุกตัว
- รายงานไม่ระบุตัวตนได้และบอกชัด — ตอบโจทย์ "กลัวถูกตำหนิ" (สาเหตุอันดับ 1)
- Feedback loop ปิดวงจร — ตอบโจทย์ "รายงานแล้วเงียบหาย"
- กรอกครั้งเดียว + human-in-loop NRLS — ลดภาระงานซ้ำซ้อน
- KPI เวลาตอบสนอง (median รับเรื่อง 20.6 ชม., ปิดเคส 8.9 วัน) — เกินกว่าที่เว็บกลางให้

**ยังขาด:**
- ข้อความสื่อสารวัฒนธรรม no-blame บนฟอร์ม ("รายงานเพื่อเรียนรู้ ไม่ใช่เพื่อลงโทษ")
- ผู้รายงานตามผลเคสตัวเองไม่ได้
- แจ้งเตือนถึงตัวคนยังเป็น in-app อย่างเดียว (มีหน้า /channels ให้ตัดสินใจแล้ว)
- ไม่มีการยืนยันตัวตน/สิทธิ์

## 5) คะแนนความพร้อมใช้งานจริง: 6.5/10

แกนหลักใช้งานได้จริง เดาได้เอง ออกแบบตรงกับหลักฐานงานวิจัย — หักจาก (ก) เซ็นชื่อ default (ข) validation เงียบ (ค) เคสใหม่ไม่รุนแรงจมหาย (ง) ไม่มีระบบสิทธิ์ — แก้ 4 ข้อนี้ได้ 8+ ไม่ยาก
